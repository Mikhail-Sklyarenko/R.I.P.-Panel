# Исправление запуска фарма через панель — v19

В логе теста 2026-09-19 общий preflight завершился ошибкой `nav preflight failed: No module named 'nav'`. После входа в Deathmatch панель повторила эту проверку и отказалась запускать боевой процесс. Поэтому одновременно отсутствовали детект, автострельба и навигация. Лог не подтверждает сброс моделей или навигационных профилей.

Причина: панель запускает `vendor/csgobot/tools/preflight.py` по полному пути. Python добавляет в путь импорта каталог `tools`, а не `vendor/csgobot`. Смена рабочей папки не исправляет это. Отдельный `tools/nav_preflight.py` уже добавлял родительский каталог, поэтому сообщал успешную проверку навигации и создавал противоречивую картину в журнале.

Общий preflight теперь также добавляет каталог csgobot относительно собственного файла. Проверки моделей, камеры и зависимостей не отключены. Исправлено устаревшее сообщение о переходе на макропатруль: при критической ошибке боевой процесс не запускается. Версия движка — `visual-nav-multimap-19`; его хеш теперь включает общий preflight.

Регрессионный тест запускает реальный проверочный файл отдельным изолированным Python-процессом из каталога бота и из посторонней папки. Проверяются настоящие навигационные ресурсы всех карт. На macOS отсутствуют Windows-зависимости pygrabber и CUDA/YOLO окружение пользователя: эти ошибки остаются отдельными причинами отказа и не маскируются.

Установка: закрыть панель и процессы бота; распаковать накопительный архив v19 в существующий корень R.I.P.-Panel с заменой файлов. Запустить виртуальную камеру OBS и FarmPanel.bat. После входа в матч ожидается сообщение `csgobot: subprocess started` либо `csgobot: joined preloaded subprocess`. Версию движка проверять в журнале боевого процесса. Аккаунты, модели и виртуальные среды архив не заменяет. Ранее собранный EXE не пересобирается.

Полный живой фарм Windows/CS2 на машине разработки не запускался. Проверен воспроизводимый отказ запуска и его исправление.
