# Phase 02.6 end-to-end

The automated scenario is `tests/test_fleet_acceptance.py::test_four_simulated_agents_commit_and_freeze_a_run_plan`. It does not call `note_prepare` or `note_commit` itself. Each agent heartbeats through `InProcessTransport` into one `Coordinator`.

## Happy path

1. One `FleetStore` and one `AssignmentBook`.
2. Four agents, `pc1`–`pc4`. Each gets `open_enrollment` and `claim_enrollment`, so each has its own token.
3. Four catalog files and four journals.
4. Each catalog has two synthetic logins. The test selects the second, `chosen`, and binds a distinct SteamID64.
5. The first heartbeat sends `catalog.snapshot()`. The snapshot has no password field. The test checks that the book status text has no `password`.
6. `draft` uses the four chosen `(agent_id, local_account_id, steam_id64, catalog_revision)` rows.
7. `begin_prepare` then `enqueue(..., "prepare")`.
8. Two ticks per agent deliver PREPARE and return the results.
9. Status becomes `prepared` only after all four.
10. `decide_commit` writes `run-e2e` before any COMMIT command is sent.
11. `enqueue(..., "commit")` and two more rounds of ticks.
12. Every slot is `committed`.
13. `enqueue(..., "verify")`. Each agent's `identity_probe` returns `SteamIdentity(Identity.GSI, steam)`. The coordinator does not supply that id.
14. `ready(..., links=healthy)` is true only after those four fresh matches.
15. `build_run_plan` freezes the roster. `account_id` for `pc2` ends with that PC's chosen local id.
16. `Coordinator.start_run(plan)` stores the plan. No gameplay backend method is required to succeed; the test backend raises if `execute` is called.
17. Reopening the same SQLite file is covered separately by `test_late_release_and_restart_do_not_invent_a_new_run` and `test_commit_decision_survives_restart_without_acks`. The panel desk reads `book.current()` on construction, so a restarted panel shows the stored preparation instead of an empty draft.

## Faults covered by tests

| Fault | What stays true | Test |
| --- | --- | --- |
| One agent is partitioned during PREPARE | The group is not READY | `test_one_offline_agent_blocks_ready_and_a_foreign_result_is_ignored` |
| Another agent submits that command's result | The result is not acknowledged | same test |
| SQLite raises while folding a result | The command stays `pending` and the retry applies once | `test_result_crash_does_not_ack_and_retry_applies_once` |
| Coordinator process reopens after COMMIT | `run_id` is unchanged and a different `run_id` is rejected | `test_late_release_and_restart_do_not_invent_a_new_run` |
| RELEASE arrives with another generation | The committed slot stays committed | same test |
| Same preparation id, different account | Catalog prepare raises | `test_catalog_generation_is_not_the_max_account_revision` |
| Older VERIFY sequence | READY is not rebuilt from it | `test_four_fresh_gsi_matches_are_ready_until_link_or_clock_breaks` |
| Agent boot id changes | The previous proof is cleared | same test |
| Clock moves backwards | Age is negative and READY is false | same test |
| Link becomes suspect | READY is false | same test |
| Revoked or never registered | Heartbeat is 403, including with the shared fleet token | `test_revoked_registration_has_no_shared_token_path_and_unregistered_is_rejected` |
| Stale catalog snapshot | The newer head remains | `test_stale_snapshot_and_empty_catalog_keep_their_head` |
| Gameplay cancel with an empty run id | PREPARE still reserves locally | `test_assignment_survives_a_cancelled_gameplay_context` |
| Wrong CA, wrong SAN, expired certificate | HTTPS heartbeat fails | `test_https_accepts_a_trusted_certificate_and_rejects_a_bad_one`, `test_https_wrong_name_and_expired_certificate_fail` |
| Cleartext bind on `0.0.0.0` | The listener does not start | `test_cleartext_lan_is_refused_and_lan_ready_is_only_configuration` |

## Not injected on four live PCs

A third agent returning a hard failure, a coordinator restart in the middle of the four-agent tick loop, and a disk error on a real LAN were not run as a separate four-PC exercise. The single-process tests above cover the state machine for those cases. They do not prove the network.
