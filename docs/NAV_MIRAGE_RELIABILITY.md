# Mirage v11: остановки на прозрачном HUD и приседание в jungle

Обновление прохода CT/окно: [Mirage v15](NAV_MIRAGE_PASSAGES.md). Добавлены нижний маршрут и определение уровня по русской подписи HUD.

Исторический отчёт v11. Актуальное кумулятивное обновление — [Dust2 v13](NAV_DUST2_CONTINUITY.md); оно включает эти исправления. Для установки используйте архив v13.

Обновление работает через существующую FarmPanel.bat и тот же процесс навигации/автострельбы. Движок: `visual-nav-multimap-11`. Выбор профиля остаётся автоматическим для Dust2, Mirage, Inferno, Vertigo и Cache.

## Что показало тестирование

Изучены видео `2026-09-15 18-03-21.mp4` (416.32 секунды) и приложенный лог. Последняя сессия лога сообщает 165.3 секунды ожидания позиции при 411.2 секунды работы и 52.4% валидных позиций. Это отдельные показатели рабочего процесса; их нельзя напрямую приравнивать к результатам offline replay.

На 40-й и 60-й секундах игрок стоит на T-side проходе. Атлас узнаёт геометрию, но старый детектор объединяет жёлтый значок и голубые участки просвечивающего неба в один компонент на тысячи пикселей. Он отбрасывает этот компонент как слишком большой. После разделения цветов проявляется вторая причина: светлое небо попадает в широкий порог белого указателя направления и делает направление неоднозначным.

## Исправления

- Жёлтый и голубой маркеры сегментируются независимо. Кандидаты проверяются по прежним ограничениям площади и расстояния от центра; небо не подменяет отсутствующего игрока.
- Для направления сначала проверяется яркое нейтральное ядро белого наконечника. Если его недостаточно, используется прежняя широкая маска. Направление выдаётся только при пространственно согласованном текущем изображении.
- Убрано повторное сканирование всех пикселей для каждого цветового компонента: используются уже вычисленные центры компонент.
- Mirage использует проверенную подсказку масштаба HUD 0.355 и поиск по всей карте перед итеративным отслеживанием. Положение не ограничивается предыдущим спавном. Учтено кольцо дальности на радаре.
- Свежий успешный глобальный результат служит новой визуальной опорой. Фоновый поиск включается при потере измерения, более старый результат не заменяет свежую опору.

## Проход jungle/window

В `resources/nav/profiles/de_mirage/traversal.json` описана двусторонняя зона приседания около узкого проёма, видимого на 175–190 секундах записи. Координаты — в системе существующего радара, нормализованы по 1023.

Ctrl добавляется к движению заранее внутри небольшой зоны, а не ко всей jungle. У границы есть небольшой гистерезис, чтобы не нажимать и отпускать Ctrl на каждом дрожании координат. После выхода приседание снимается. Оно также снимается при остановке, паузе на противника, невалидной/устаревшей позиции, смене карты и закрытии контроллера. Ctrl обслуживает тот же watchdog, что WASD. Shift не добавлен. В самом низком проходе скорость закономерно ниже из-за приседания.

Проверка включает симуляцию движения с низким потолком, который пропускает игрока только с Ctrl, в обе стороны. Это проверяет поведение контроллера и отпускание клавиш, но не физику настоящей игры. Прочие прыжки, подсадки и взаимодействия не объявляются реализованными без проверенного описания перехода.

## Установка

Закрыть панель и процесс бота. Распаковать `farm-panel-mirage-v11.zip` в существующий корень R.I.P.-Panel с заменой файлов. Включить виртуальную камеру OBS, запустить FarmPanel.bat. Старый собранный EXE этим архивом не пересобирается; используется существующий запуск из исходников.

В CMD для тренировки с ботами:

```cmd
cd /d C:\Users\FermK\Downloads\R.I.P.-Panel
set CSGOBOT_NAV=1
set CSGOBOT_NAV_READ_ONLY=0
set CSGOBOT_NAV_MODE=expanded_roam
set CSGOBOT_NAV_PACK=auto
set CSGOBOT_TARGET_MODE=ffa
set CSGOBOT_AUTO_ACTIVATE=0
cd vendor\csgobot
venv\Scripts\python.exe -u run.py
```

CapsLock активирует бота, Ctrl+Q завершает работу. В логе должна быть версия `visual-nav-multimap-11` и подтверждённая карта Mirage.

## Достоверность результата

Кадры этого тестового видео не добавлялись в атлас. Исправления сегментации проверены на нескольких кадрах записи, поэтому эта запись является набором разработки; для независимой итоговой оценки нужна новая игровая сессия. Результаты replay характеризуют измерение позиции и задержку, а не успешное прохождение каждой точки игры. Паузы при смерти, меню, противнике или отсутствии достоверных координат остаются необходимыми.

Пройдено 126 автоматических проверок. На общем фрагменте 20–100 секунд: 202/800 (25.25%) принятых измерений до исправления и 761/800 (95.12%) после. Наибольшая серия невалидных кадров на этом фрагменте: 46.4 с → 3.1 с. Начальные 10 секунд обоих прогонов исключены из сравнения, чтобы не смешивать его с холодным запуском.

Полная запись: 3820/4160 (91.83%) принятых кадров; свежих к концу обработки — 3748. Самая длинная серия невалидных кадров, включая меню/смерть, — 3.1 с. Медиана обработки — 76.26 мс. Детали: `resources/nav/profiles/de_mirage/validation-v11.json`.

Длинные провалы 70.8–73.9 с (открытая игровая консоль), 111.6–114.7, 169.4–172.4, 206.5–209.4, 323.5–326.5, 332.0–334.8 и 362.1–365.0 с (смерть/возрождение) проверены визуально.
